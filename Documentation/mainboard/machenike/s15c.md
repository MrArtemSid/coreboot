# Machenike S15C (V155PNPQ-HMx)

This page describes the coreboot port of the Machenike S15C
(also sold as "Star 15" / 星辰15), board V155PNPQ-HMx.

The board is a Uniwill-family white-label design (subsystem ID
`1558:0155`, CLEVO/KAPOK) closely related to the Clevo NP50PNP family;
the port was bootstrapped from the System76 `system76/adl` variant
`gaze17-3060-b`.

## Specifications

- CPU: Intel Core i5-12500H (Alder Lake-P); other 12th gen H-series
  SKUs are wired the same way
- dGPU: NVIDIA RTX 3060 Mobile (GA106M) on PEG 00:01.0, x8 link;
  RTX 3050 variants of the same chassis exist
- PCH: Intel Alder Lake-P PCH-P (eSPI)
- RAM: 2x DDR4 SODIMM (DDR4-3200), SPD read over SMBus at 0x50/0x51
- LAN: Intel I219-V
- Wi-Fi/BT: Intel CNVi (AX201-class)
- Audio: Realtek ALC256
- EC: ITE IT5570E (rev 6) at eSPI IO 0x2e, stock ITE firmware
- Flash: Macronix MX25L25645G, 32 MiB
- Touchpad: FocalTech FTCS1000 (I2C-HID, HID `2808:0101`) on I2C0

## Flash layout

| Region             | Offset    |
|--------------------|-----------|
| Descriptor         | 0x000000  |
| GbE                | 0x001000  |
| Intel ME (CSME 16) | 0x003000  |
| BIOS               | 0x1000000 |

The descriptor is unlocked (all flash masters have full access), but
the vendor firmware enables BIOS write protection
(`BLE` + `SMM_BWP`, enforced by an SMM handler): **internal writing is
blocked, reading is not**.

## Dumping the flash

A full read works from the running system with flashrom; the kernel
SPI driver must be unbound first so flashrom can use the raw
controller interface:

```console
$ echo 0000:00:1f.5 | sudo tee /sys/bus/pci/drivers/intel-spi/unbind
$ sudo flashrom -p internal -r backup.rom
$ echo 0000:00:1f.5 | sudo tee /sys/bus/pci/drivers/intel-spi/bind
```

Read the image twice and compare (`cmp`) to make sure the dump is
stable. Keep the vendor image: it is the only recovery path.

## Boot Guard status

The flash contains a provisioned Key Manifest (`__KEYM__`) and Boot
Policy Manifest (`__ACBP__`). The enforcement state can be read from
the running system: the Startup ACM records its decisions in
`MSR 0x13A` (`BOOTGUARD_SACM_INFO`, same check as
`intelmetool -b`; the tool itself does not know the Alder Lake HECI
device ID yet):

```console
$ sudo modprobe msr
$ sudo rdmsr 0x13A
130000007f
```

Decoding (bit 32 = Boot Guard capability, bit 5 = measured boot,
bit 6 = verified boot) gives: measured **and** verified boot enforced
with PTT. An unsigned coreboot image will not boot on this board as
shipped.

The HECI controller's PCI configuration register 0x40 (HFS) has bit 4
set, which historically indicates that Boot Guard keys may be
overwritten or wiped (developer/manufacturing configuration). Whether
the FPFs can actually be rewritten on this board with Intel FPT is
not verified yet.

## Programming

Only external flashing (e.g. CH341A with a SOIC-8 clip on the 32 MiB
MX25L25645G) is possible until the write protection situation changes.
Do not attempt internal flashing with the vendor firmware; it will be
refused by SMM write protection.

## Status / TODO

- GPIO configuration was captured from the running vendor firmware
  with inteltool and converted with intelp2m; pads marked TODO in
  `gpio.c` and `devicetree.cb` (USB port indices, PEG clock
  source/req, dGPU pad polarity) still need schematic confirmation.
- The stock ITE IT5570E EC firmware handles fans/battery
  autonomously; a coreboot EC driver has not been written yet.
- Boot Guard: verified boot enforced (see above); flashing requires
  either disabling/rewriting the FPFs or a signed payload.
